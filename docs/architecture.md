# 架构

CPscore 的八个独立 Skill 以 `SKILL.md` 指挥宿主、`references/` 保存专业知识、可选脚本检查覆盖范围。OIBlogScore 沿用这一职责划分，增加面向 Git 博客仓库的持久化队列、文章依赖快照和可回滚编辑。审查工作交给真实 Agent，而不是把关键字匹配当作证明检查。

- `repository`：Git 顶层和 NUL 分隔清单命令、路径约束、原子状态文件、互斥锁。
- `discovery` 与 `discovery.manifest`：枚举已跟踪和未忽略的未跟踪文件；建立局部引用图和传递依赖。引用解析和闭包遍历位于 `discovery.dependencies`；自动辨识失败则保留理由或要求显式声明。
- `audit` 与 `audit.results`：每篇每维度一个任务；任务票据区分 Full 重启，指纹包括路径到原始字节 SHA-256 的映射、未解析依赖、CLI 源文件和规则。Git commit 间变动补充文件哈希；无法检查旧 commit 时依赖当前快照哈希。
- `repair` / `verification`：同作者参考统计、只允许内置的完整行替换、写前日志、写后精确核对、按编辑 ID 或文章撤销。`repair.style` 只产生统计，`repair.diff` 只渲染差异，`repair.journal` 检查冲突并维护写前事务；语言修复编排不承担这些实现细节。
- `reporting`：依据当前快照裁定缓存有效性；独立统计发现、审查及修复验证。

状态保存在目标仓库 `.oiblogscore/`，不是审过的博客源文件。请把该目录加入 Git 本地排除，并避免保存访问凭据或发布私有报告。不同 Agent worker 可并行读取相同输入并在各自位置写结果；CLI 提交由单一写锁序列化（锁忙时由调度方稍后重试）。没有自动启动外部 Agent 的服务。强制终止留下 `lock` 时先确认没有进程还在运行，再移除锁并 `resume`。修改期间不要同时用外部编辑器改同一文件；工具对普通并发编辑有两次读前检查，但不是对恶意文件系统竞争的沙箱。

规则缓存默认检查目标仓库 `skills/` 和 `resources/` 的 Git 可见文件；用 `rule_paths` 指定其他仓库内位置。使用可信环境变量 `OIBLOGSCORE_REFERENCE_ROOT` 可以把外部 OIBlogScore checkout 中的 `skills/`、`resources/` 正文纳入指纹；没有链接跳转，不由被审仓库配置自动指向外部。宿主模型与额外提示仍不自动读取；变更时递增 `rule_version` 或使用 `--full`。语法、类别、作者和依赖识别都是启发式。配置可为任何 Git 可见依赖补边，包含公共头文件、独立代码和资源等。

## 状态与恢复边界

| 操作 | 权威状态变化 | 拒绝或恢复条件 |
|---|---|---|
| scan / report | 重算发现快照与派生报告，不替换任务结论 | 非法配置或文件读取错误失败；已报告的缺依赖不算完整覆盖 |
| audit full / incremental | Full 为所选任务签发新票据；增量仅保留输入一致的记录 | 同任务只存在一张有效票据；队列由 `audit.json` 派生 |
| submit / resume | 匹配当前指纹和票据后持久化结果；恢复重建队列、保留原选择 | 过期和已终结票据拒绝；`NOT_CHECKED`、`NEEDS_CONTEXT` 可补交 |
| repair / rollback | 先持久化 `pending`，再替换正文，最后落盘日志结论 | 旧字节保留时中止本次修复；新字节完全吻合时确认；两者都不匹配时拒绝自动处理 |
| verify | 读取 journal 和当前正文比较，不改正文 | 日志尚未收敛或正文不一致，返回失败 |

快照在单次发现中对文本解析和摘要使用同一份字节，但不是整个工作树的文件系统事务。`audit.json` 是任务权威；`queue.json`、`manifest.json` 与报告各自原子替换，不保证几个文件成组提交。中断后使用 `resume` 重建。用户编辑器和 Git 不参与 CLI 写锁；对恶意并发重命名或系统掉电没有原子跨文件保证。保留 `.oiblogscore/` 内的原稿与日志，不在权限不可信的目录里共享状态。
