## 下一轮复核（同一分支，保留上一轮未提交工作）

起点仍为 `64950590e19b76219f8e0555adbd0956259b5bc1`，47 个已跟踪文件有修改、3 个未跟踪文件、无暂存。起点门禁和 63 项测试重新通过。先运行两个失败回归：将修复结果纳入 HEAD 后仍能撤销；在文章临时文件 `fsync` 时写入外部改动仍会被后续替换覆盖。现将最后检查放到临时文件持久化之后，并要求回滚基线仍等于 journal 原稿。故障测试另覆盖 ENOSPC、`os.replace` 失败、正文成功而最终 journal 更新失败、损坏的 pending、外部编辑和索引冲突。无冲突且原稿仍在时可中止；新字节匹配时可确认；两者均不匹配、journal 损坏或基线变更时须人工介入。保留 journal，不自动写回。

发现阶段仍用同一份首次读取字节做解析和摘要；提交快照前对已经读取的仓库输入再做字节摘要比较，检测持续性变化时整次失败。不是基于 mtime，也不能检测 ABA、第二次读取后的修改、文件清单改变或保证多个文件属于同一时刻。写入最终检查和 `replace` 之间也没有跨平台原子比较并交换；不允许与不受信任的外部写入者一起运行。现拒绝多硬链接的修复目标。Git 忽略规则仍定义未跟踪范围，不能用于证明整个磁盘发现完备。

| 状态 | 进入和退出 | 待办、缓存与报告 |
|---|---|---|
| NOT_CHECKED / NEEDS_CONTEXT | 尚未提交或缺证；同一有效票据允许补交 | 待办；记录可保存但不算完成；不能汇总为 COMPLETE |

`verify` 重算修复及汇总，不将 `NEEDS_CONTEXT` 改为 `PASS`。缓存按路径/维度、内容、依赖、规则字节、配置、票据绑定；外部模型、参数或未登记的 Prompt 变化必须更新 `rule_version` 或 Full。报告是可刷新派生文件，扫描失败不会声称旧文件是新报告。

知识定点复核：Beats 声明只覆盖 chmin + 求和，补上初始势能、部分覆盖增量和混合 add 的合法反例；Knuth 声明给出转移和明确充分条件，单调性继承仍为 `needs-review`。整体二分限定单位插入、非负计数，允许负坐标但不允许负更新；每轮分桶重放、清空 Fenwick，非递归且不重排序，`U+1` 只作为哨兵。现有穷举 oracle 对照首个满足条件的前缀。Blackout 2 仍是离线只删边变体。其他高风险专题未提升核验状态。

盲测基础设施：支持两个条件共享 seed 顺序；F1 无分母时返回 null。合成比较仅测试工具，不是 Agent 输出。真实运行时另存模型、采样参数、Prompt/Skill/Catalog 摘要、相同时间和 token 预算、权限清单、seed、原输出和工具日志；私有答案、分组映射不交给 Agent。24 题仍采用每题一个自动主判定，理由、引用语义及多缺陷给分尚需独立人工。不得把资料命中率称为证据准确率。

### 文件一致性等级与恢复

报告现在标注 `snapshot_consistency: revalidated`：解释文本与首次摘要来自同次读取，已观察的仓库输入经第二次验字节，不是 `repository_snapshot_consistent`。不同文件的两次读取都可能落在不同时间；新增路径、过滤器配置、外部规则读取与最后一次读后发生的变化不是原子冻结。工作区和 Git tree 不是可互换的视图：切换到 tree 会遗漏未提交及未纳入 tree 的工作，未采用。

对于缓存，最终观察同样的内容、依赖和规则允许相同输入语义；不承诺观测 A→B→A 的中间时刻。对于写入，回到同一内容并不证明同一文件身份，也不能保证父目录或 HEAD/索引未被更改。最后路径复验仍与 `replace` 分离，不执行可疑外部写入者共存的修复；这不是跨平台 compare-and-swap。已经检测到的路径、链接、字节和 Git 冲突拒写。

`repairs.json` 是修改原稿和恢复的权威，`audit.json` 是审查票据权威；报告是派生缓存。从未反向由报告写 journal。正文替换成功但报告失败时，旧报告可能仍留在磁盘；命令失败不是旧报告的新鲜度证明。保存旧报告供诊断时应记录运行时间，消费者须运行 `resume` 后 `report`、检查退出码，不仅查看旧文件。pending 在原稿、新稿或冲突三种状态以字节决定；确认前不覆盖第三种状态。两次恢复不应重复修改正文。不宣称支持任意旧版本日志的自动升级。
