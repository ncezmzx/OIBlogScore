# Treap：双序与随机树高

## 问题模型

动态维护有序多重集，支持插删、秩和前驱。讨论 split/merge Treap；重复键可用计数或 `(key,unique-id)` 严格排序。

## 算法原理

每节点有 key 与随机优先级：中序按 key，父按优先级支配子。split 递归切一侧并重算，merge 在两根中取优先级较优者再接合适的一侧。

## 成立条件

merge 的整棵左树必须在 key 顺序上先于右树；对于隐式 Treap 用序列下标顺序语义。期望界需要随机独立的优先级相对序，及固定的、不依赖优先级的操作输入。

## 关键不变量

每次 split 后元素恰好按阈值分两边；merge 后合并中序等于两输入中序拼接，同时保持堆序和子树 size。

## 证明路线

对节点数归纳：根的 key 指定 split 仅一侧可能跨阈值；merge 根必须是两棵树中优先级最优者，剩余子问题保持分离。每对严格的 key/priority 序唯一确定对应笛卡尔树。

## 复杂度推导

对固定 key，秩距 d 的顶点是其祖先当且仅当优先级在包含端点的 d+1 个键中最佳，概率 1/(d+1)。对左右方向求和期望路径 O(log n)；固定阈值的 split 和键域分离的 merge 沿相应搜索路径。单次最坏可 Θ(n)。

## 错误与反例

`merge({3},{2})` 不能用于 key 有序树，即使优先级合法。优先级与递增键同序可能构造整条链，破坏“任意一次对数”的说法。

## 性质边界

期望不是最坏，且有限 RNG 平局需处理；反向标记只对隐式序列模型有意义，不能随意反转按 key 排序的集合。

## 审稿检查

检查分裂阈值（< 还是 ≤）、重复键、子树 size/pushup、随机源与 seed 模型。用插入两个重复键后删除一个，再查界或秩作对照。

## 区别与联系

Splay 不用随机数，基于访问序列摊还；Treap 的平衡约束来自笛卡尔树，不可把两者的证明互换。
