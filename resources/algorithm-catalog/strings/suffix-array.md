# 后缀数组：倍增、哨兵与 LCP

## 问题模型

以字典序排列各后缀，LCP 数组记录相邻后缀最长公共前缀。区分排序后缀和循环移位。

## 算法原理

加一个唯一最小哨兵后排序循环移位；倍增用长度 2^k 的两段 rank 对排序，再重编号。移除哨兵后可用 Kasai 把相邻 LCP 线性算出。

## 成立条件

哨兵严格小于全部合法字符且唯一。直接排序后缀的变体需给越界右半段专用更小秩；平秩两关键字相同才可同组。

## 关键不变量

秩编号保序并且恰好标记当前长度前缀相等类；Kasai 下一轮已知公共前缀至少可以从上次长度减一开始（对正确邻居论证）。

## 证明路线

按倍增层证明 rank 对的字典序等于拼接串序；公共前缀对应后缀数组的连续区间，因此两后缀 LCP 等于对应相邻 LCP 的区间最小值。

## 复杂度推导

每轮两关键字计数排序 O(n)，O(log n) 轮共 O(n log n)。比较排序每轮 O(n log n)，合计 O(n log² n)。Kasai 成功扩展总量 O(n)，仅需 O(n) 额外数组。

## 错误与反例

`aa` 的两个循环移位完全相同，但后缀 `a` 严格小于 `aa`；若用原下标打破循环平局得到 `[0,1]` 而非 `[1,0]`。

## 性质边界

得到 rank 不代表有 LCP；求任意两点 LCP 若无 RMQ 预处理，还要计区间扫描或查询结构成本。

## 审稿检查

核对空输入、重复字符、rank 重建、哨兵剥离后的索引变换、LCP[rank] 指向前一项还是后一项；使用朴素后缀排序对照。

## 区别与联系

后缀自动机合并 endpos 类，不能直接把其状态顺序当作后缀字典序。字符串哈希也只给概率型相等证据。
