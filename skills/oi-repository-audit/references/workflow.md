# oi-repository-audit 执行协议

## 输入规格

目标 Git 仓库路径、全量/增量/筛选请求、规则版本及可访问的必要依赖。

## 工作流与资源

队列 JSON 每项有 path、dimension、ticket、fingerprint、inputs；提交时依据当前输入复验。不要并行写同一个结果文件或状态。未知依赖先补配置，再重新拿票据；CLI 锁冲突应稍后重试。

## 输出规格

报告与清单路径、审查与缺口数、规则与输入指纹；持久化逐维票据。

## 失败处理

CLI 不可用时可以只读人工列清单、复核有限样本，但不得声称缓存或覆盖已验证；后续修复需授权。

## 验证过程

使用 `dependency_edges` 区分配置和启发式命中。可见但缺规格、编译参数或依赖时交 `NEEDS_CONTEXT` 并写明缺项；它仍在待办队列，不算审完。

在当前快照重新生成报告；核对目标过滤器并不降低全仓分母，回查 NOT_CHECKED 和依赖缺失。

## 示例

只检查 `notes/` 的证明：`oiblogscore audit . --path notes/ --dimension proof`。即使队列清空，也不能把未查技术维度计入全仓已审。
