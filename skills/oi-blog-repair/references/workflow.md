# oi-blog-repair 执行协议

## 输入规格

原稿及编辑授权，修复模式和路径；若有同作者原作，记录确认身份的依据。

## 工作流与资源

独立段落白名单不等于对任意 Markdown 的语义分析。先从不同位置取同作者样本，看句长、短语、语气与术语；不能仅由署名相同断定同人。先记录问题类别，再预览 Diff 所属段落。

## 输出规格

候选分类、条目位置、理由、原句/建议、Diff、风格证据；没有修改也要报告。

## 失败处理

遇到脏文件、缺 CLI 或语义不确定时仅列建议；不退化成直接覆盖文件。

## 验证过程

对所有写入运行 verify，检查其他技术内容字节、改前后语气和报告中的复审任务。

## 示例

“下篇再聊。。”可由白名单删一个句点；“只能选最小的”不得改为“可以选最小的”，它改了量词。
