# oi-repair-verify 执行协议

## 输入规格

两份文稿或修复日志、文件当前版本、用户授权和原文证据。

## 工作流与资源

把原文、日志预期和当前工作树分别读取。区分“候选不在白名单”、“写入已中断”和“现有文件已被外部更改”。只有日志期望字节与工作树匹配且无暂存变更时，才可在授权下撤销。

## 输出规格

逐变更检查结果、局部语义理由、精确验证状态、复审/冲突/回滚 ID。

## 失败处理

遇到工具拒绝或外部改动，停止写入并报告原本/预期/当前差异；不强制回退。

## 验证过程

分别核对编辑前后字节、活动 journal 和当前文件；`PASS` 仅表示允许的精确文字变更通过，不能替代受影响技术维度的重审。Catalog 可供重审，不用于放宽 Diff 守卫。

verify 成功只覆盖工具白名单；另外检查当前文章的技术结论是否已按新任务重审。没有活跃修复时 `verify` 的空结果是 no-op，不是通过；`repair-run.json` 中的 dirty、非 UTF-8 和拒绝必须分别报告。

## 示例

若 Git 已提交修复结果而旧日志仍活跃，不强制 rollback；如需撤销，由作者审查新的变更。

日志期望尾句已去重复标点，但用户又往文件新增一段：验证失败，不能整篇回滚覆盖用户段落。
