# oi-code-review 执行协议

## 输入规格

代码与行号、算法规格、输入范围、语言标准和环境；远端依赖不默认执行。

## 工作流与资源

核对 [C++ 语义](cpp-semantics.md) 与 [实现、资源和判级](cpp-implementation.md)。

## 输出规格

带分类和触发证据的静态结果，以及实际执行过或未执行的检查。

## 失败处理

缺编译规格时对拓展语义给条件结论，编译失败不自动归为算法错误。

## 验证过程

若未实际编译运行，只交付静态结论；若经授权运行自写最小 fixture，记录语言模式、编译器、参数、输入与预期，不能把一次运行当成原文代码的全面验证。

重走每个报告的合法触发路径，按 C++ 实际表达式类型核验，区分理论和环境假设。

## 结论与证据

代码与题目模型不一致、溢出、UB、越界、递归/内存风险按影响判 `FAIL`；缺实现、编译规格或输入范围用 `NEEDS_CONTEXT`；文章没有代码且该维度确实不适用时用 `NOT_APPLICABLE` 并说明理由；未完成静态检查用 `NOT_CHECKED`。重复点、重边、重复测试数据和极端结构必须单独核对。

## 示例

对于 `int64_t z = a*b`，先追踪 a、b 的类型及范围。若均为 32 位有符号整数，50000×50000 已在赋值前超界；若类型未给，报告条件性风险而不是无条件 UB。

约束允许两个 50,000，`long long r=a*b;` 中 int 乘积超出 32 位 signed int；先在乘法操作数提升类型。
