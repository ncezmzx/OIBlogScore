# C++ 审查：资源、实现技巧与判级

## Recursion Depth

列最坏输入形态（链树、退化搜索树），估算帧数、每帧有无大数组或非尾递归及平台栈。分治深度 O(log n) 并不保护分治内部 DFS。无可确认栈限时给条件化资源风险，不宣称必崩。

## Memory Allocation

追踪节点池、vector 容量与多测重置。按 `sizeof(Node) × capacity` 加上邻接表、额外复制和峰值重分配。`reserve` 不改变 size，不能对预留但未构造的 vector 元素用下标写；访问越界不是性能问题。

## Lazy Propagation

为 `apply(tag,node)` 和 `compose(new,old)` 写函数等式；验证点查前 push，回溯 pull，不对叶访问不存在孩子。覆盖后加与加后覆盖是不同测试，应独立跑逻辑轨迹。空区间单位元和传递标记有效性要与更新契约一致。

## Persistent Data Structures

每次写入要能指到独占新节点，旧根与共享孩子不可修改。若查询会 push 懒标记，必须保持只读或复制；不能因函数名是 query 就视为无副作用。测试分叉版本、旧根重读、池扩容与编号 0 的空节点。

## Fast I/O

人工读样例流核对负号、空白、EOF、多测、缓冲刷新；交互输出要求及时 flush。关闭 iostream 同步后不要依赖与 stdio 的相对顺序。自制 reader 需要正确区分 EOF 与字节；`getchar()` 接收类型应为 int。只在 I/O 契约符合时把差异判为纯性能。

## Time Complexity Pitfalls

审查按值传递 vector、循环里 `erase(begin())`、字符串不断拼接和比较、隐式 map 插入与多测清空。q 次 `erase(begin())` 对 n 元素 vector 每次后移剩余项；q=n 时为 Θ(n²)，而维护起始索引不搬元素。给调用次数与每次代价，不以实测毫秒取代上界。

## 分类和报告

- 算法逻辑：即使理想整数模型也无法返回正确答案（给合法输入和最优基准）。
- 实现不符：算法有效，代码与规格/不变量不匹配（给变量轨迹，例如错端点）。
- C++ 语义：标注 UB 或有定义但错误的转换/回绕，附语言模式和触发路径。
- 资源或性能：逻辑输出正确，但已证/疑似超限；把复现条件与严重度分离。
