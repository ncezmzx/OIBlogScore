# 证明审查协议：命题、证据与依赖

适用：文章中的数学结论、等价化简、算法正确性和数据结构正确性。本协议不把测试当成全称命题的证明。不覆盖成本分析的具体算式。先固定原文版本、题目版本和证据范围，再选择[构造与状态证明](methods.md)或[成本、随机与反例](cost-and-witness.md)。

## Definitions and Preconditions

1. 为命题登记 ID、原文行、变量定义域、量词顺序、输入边界、前置引理和结论；区分原题承诺、实现检查和审查者补充。
2. 将条件代到每次变形：除法检查除数、单调变换检查方向、约去模项检查单位、最小值检查存在（尤其空集合）。
3. 通过标准：所有符号在使用点有定义，每个步骤的条件由规格或已证明命题推出。典型错误：把“对每个输入存在一个策略”换成“存在一个通用策略”。报告 `D1 @ L12: 量词 ∀x∃y；正文执行 ∃y∀x；缺失统一性证明`。

## Lemma Dependency

1. 将定义、引理、主定理、外部引用分节点；边方向统一为「当前节点依赖的前提」。可用原文行范围给每个节点定位。外部定理记录出处和当前参数如何满足假设。
2. 按拓扑次序检查。若出现循环，确认是否能改写成以同一良基参数归纳（此时使用更小规模的实例，而非同一命题互证）；不能将证明环当作已知事实。
3. 通过标准：图无环，每条依赖边有上下文中成立的实例，主定理无未结案的可达前提。报 `T -> L2 -> L1；L1@L9 无证；T 被阻塞`。模板与独立检查器见 [依赖记录](ledger.md)。

## Forward Implication

对 `A ⇒ B` 固定一个满足 A 的任意对象，从 A 出发推导 B；构造时给出合法性和产物的目标性质。检查是否偷偷使用 B、是否依赖一个不一定存在的最优对象。结案须覆盖 A 的每个允许分支；否则给 `A→B / 失败步骤 / A 的合法输入 / 当前结论`。

## Reverse Implication

单独创建 `B ⇒ A` 节点；从 B 的任意对象重建 A 或证明条件必要。复用的引理需方向合法，不能把不可逆变形反推。如 `x=1 ⇒ x²=1` 不可逆，在整数域 x=−1 是反例。报 `B→A / FAIL / x=−1`；即使正向通过，也不得给等价式 PASS。

## 交付状态

- `PASS`：必要检查已完成，报告至少含关键条件、依赖链和两方向（如适用）的独立依据。
- `FAIL`：给出合法反例或明确的无效推导；区分“现有证明无效”与“命题为假”。
- `SUSPECTED`：指出已审但不能确认的具体疑点与影响；未读的适用材料用 `NOT_CHECKED`。
- 每条记录含 `命题ID / 方向 / 位置 / 条件 / 依赖ID / 判断 / 依据 / 缺失项`。覆盖率只说明读取与登记，不是正确性证书。
