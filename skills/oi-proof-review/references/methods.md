# 构造与状态证明审查

每个适用方法按「定位 → 逐步骤验证 → 判断 → 结构化证据」执行。其前提和通用状态见 [证明协议](protocol.md)。

## Induction

固定良基参数（长度、操作次数或拓扑序），先逐个验最小允许值，再核验归纳步调用严格更小的实例且满足同一前提。通过：全部基例成立，每步不会调用规模不减的子问题。典型错误：对区间 `[l,r]` 在 l=r 时仍递归 `[l,mid]`。报 `参数 / 基例 / 子实例 / 严格下降量 / 首个断点`。

## Invariants

把不变量写成在指定程序点对状态成立的谓词；查初始化、每条分支保持、退出时如何推出后置条件。另证终止（如非负整数严格下降）。通过：无未覆盖的状态修改或异常出口。例：二分宣称答案在 `[lo,hi]`，却在 `mid` 仍可能是答案时执行 `hi=mid-1`。报 `程序点 / 谓词 / 分支 / 是否保持 / 后置条件`。

## Exchange Arguments

选一个与贪心已定前缀一致的最优解，明确移除和加入的对象，逐条验证可行约束与目标不劣，并证明一致前缀变长。若交换破坏另一个约束，不能只比较被换对象的局部权重。区间调度按最早结束交换时，必须核对端点相接算不算冲突。报 `最优解形态 / 替换 / 可行性 / 目标差 / 前缀推进`。

## Greedy Correctness

写出候选集合、选择规则、平局处理。先验证安全选择（交换、割或 stays-ahead），再证明残余实例仍是同类并匹配全局目标。通过不能仅凭每步合法。反例：按最早开始选不交区间，`[0,9]、[1,2]、[3,4]` 得 1 而可得 2。报 `候选 / 安全性引理 / 残余实例 / 终止 / 反例`。

## DP Correctness

将字面状态翻译为解集合；证明转移构造出的候选都合法，以及任意合法解都被某个候选覆盖。对计数另证唯一分拆。再验基例、不可达值、计算顺序、答案提取与滚动内存。若状态省掉了上一颜色但转移禁止同色相邻，两个相同数值状态可能拥有不同的未来。报 `状态ID / 两方向 / 基例 / 依赖序 / 读写位置`。

## Graph Algorithm Correctness

先核对有向性、重边、自环、权值约束、连通性，再记录图模型与原问题之间双向保真。依据实际算法绑定证书：最短路给路径与不可更短的论证，最大流给可行流和等值割。示例：Dijkstra 的“定点后永久最优”不能无条件用于负边。报 `图模型 / 模型方向 / 证书 / 边界 / 不符实例`。

## Data Structure Invariants

为抽象接口与物理表示建立关系，逐一检查原子操作、懒状态和外部暴露顺序。检验 if/push/pull、版本结点是否可共享、空节点语义。通过：每次逻辑更新后的可观察结果等同朴素结构。典型错误：先加 2 再覆盖 4，反序合成误得 6。报 `操作轨迹 / 抽象预期 / 实际表示 / 首次偏离位置`。
