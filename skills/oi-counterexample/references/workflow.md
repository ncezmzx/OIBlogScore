# oi-counterexample 执行协议

## 输入规格

一条可否定命题、输入范围、待审算法的真实变体，以及期望值判定方式。

## 工作流与资源

按规模和复杂性分级：先穷举小规模结构，再筛边界与平局，最后才定向采样。可信 oracle 不与待审算法共享关键推断；测试时同时核查规格和输出格式。

## 输出规格

合法样例、独立期望、实际轨迹、差异与最小化尝试；无反例则给搜索域和预算。

## 失败处理

算法行为未明确时不要补写代码再把失败归咎原文。没有 oracle 则先手算或标记未查。

## 验证过程

缩小见证后重新检查所有输入前提，并记录正确 oracle 与待否定方法的不同结果。只击穿证明的一步时，不能把见证升级成命题反例。

缩减后重验所有前提与独立答案；记录比较的是哪一个输出字段。

## 结论与证据

找到合法反例是该命题的 `FAIL` 见证，不是文章其他维度的 `PASS`；搜索无发现只表示预算内未发现，必须保留 `NOT_CHECKED`。缺规格、oracle 或输入范围用 `NEEDS_CONTEXT`；该维度确实不适用用 `NOT_APPLICABLE` 并说明理由。

## 示例

对非负边模型，含负边的最短路见证不合法；可用它说明不能去掉非负前提，但不能反驳原模型。

文本 aaaa 与模式 aa：枚举起点 0、1、2；若 KMP 命中后清零得到 0、2，合法且独立证实漏 1。
