# 图、数据结构与内存复杂度

## Graph Algorithm Complexity

以堆 Dijkstra 为例，定点后每条出边被查看一次，每次严格成功松弛最多插入一条堆记录，故 O(E) push/pop。懒删除版本堆峰值可至 O(E)，按 O(log(E+2)) 算；可 decrease-key 且每点仅一项的实现按 O(log(V+1)) 算。若存邻接矩阵则扫描邻点为 O(V²)，与邻接表实现不同。Dinic 应分 BFS 次数、当前弧推进与增广路径长度推导；单位容量不能直接当作单位网络。

## Segment Tree Operation Counting

普通连续区间在每层最多两个部分交叉节点，递归展开这两个节点并访问其兄弟，访问量 O(log n)。这不证明 Beats 的条件停止界；若递归到许多完整覆盖节点的子节点，一次可超对数，需势能或更细结构证据。多维线段树每访问外层结点还访问内层结构，分别估计组合访问，并核对局部压缩后的实际尺寸。

## Data Structure Complexity

塑造可收费的量：Fenwick 按置位变化，平衡树按高度，持久化点更按复制路径。值域 U 的隐式树 q 次点更的节点界是 O(q log U)，和元素数量 n 无关；把所有历史版本保留时不能只算一个版本节点。预处理、空节点默认值计算、多测重建及日志回滚都算实际操作。

## Memory Complexity

画时间轴计同时存活对象：输入、建图、副本、堆、栈、已分配但仍保留容量的容器、持久化池。归并写生命周期：每层只共享一个 O(n) 工作缓冲时空间 O(n) 加栈；若每个区间的中间数组全部缓存，层层共 O(n log n)。例：4×10⁶ 节点，结构按已确认 ABI 为 24 B，仅池约 91.6 MiB；容量扩张时新旧区可同时存在，不得以 size 代 capacity。注明测得峰值与理论上界的区别。
